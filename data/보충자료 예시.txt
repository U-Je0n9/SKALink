그동안 여러분은 주로 LLM 기반 생성형 AI를 중심으로 학습해왔습니다. 이는 지금까지 시장에서 언어 데이터 처리 수요가 압도적으로 많았기 때문인데, 최근에는 Physical AI(로봇, 자율주행 등 물리적 세계와 상호작용하는 AI)가 확산되면서 이미지·영상을 다루는 비전(Vision) 모델에 대한 이해도 함께 필요해지고 있습니다. 마침 관련 면접을 준비하며 질문을 주신 분들이 있어 이번 기회에 전체적으로 한 번 정리해서 공유합니다.

"LLM 먼저 배우셨든, 비전 모델 먼저 배우셨든,  Physical AI 시대에는 결국 두 축 모두 필요합니다. 판별형·생성형 비전 모델을 기준으로 LLM과의 구조적 차이를 중심으로 비교했습니다.

AI 비전 모델 서비스, LLM과 어떻게 다를까?

"AI 비전 모델"이라는 말은 한 가지를 가리키지 않습니다. 크게 판별형(Discriminative)과 생성형(Generative), 이 두 갈래로 나눠서 이해하시면 훨씬 명확해집니다. 그리고 우리가 배운 LLM은 이 중 생성형 쪽에 속하는 텍스트 버전이라고 보시면 됩니다.

**1. 판별형 비전 모델 : "인식하는 AI"**

이미지를 입력받아 "이게 무엇인지" 판단하는 모델입니다. YOLO(객체 탐지), ResNet 등(분류), Segmentation 모델이 여기 속합니다. 출력은 라벨·좌표·마스크처럼 "판단 결과"이며, 무언가를 새로 만들어내는 것이 아니라 이해·분류하는 것이 목적입니다. CCTV 분석, 제조 결함 검사, 리테일 분석 같은 서비스가 대표적입니다.
LLM 서비스와 비교하면 다음과 같은 구조적 차이가 있습니다.

**모델 서빙 방식** - LLM은 보통 텍스트 스트리밍 기반 API 호출 구조(토큰 단위 응답)인 반면, 판별형 비전 모델은 이미지·영상 전처리 파이프라인(리사이즈, 정규화), 배치 추론, GPU 메모리 관리, 실시간 프레임 처리 같은 이슈가 추가됩니다.

**데이터 파이프라인** - 이미지·영상 데이터는 저장·전송 비용이 크고, 스트리밍 처리(WebRTC, RTSP 등)나 비동기 큐 처리 구조가 필요한 경우가 많아 일반 웹 서비스나 텍스트 기반 LLM 서비스와는 다른 인프라 설계가 요구됩니다.

**지연시간(latency) 요구사항** - 실시간 비전 서비스(CCTV 분석, 실시간 객체 탐지 등)는 응답 속도에 훨씬 민감해서, 엣지 추론이나 모델 경량화(quantization, ONNX 변환) 같은 주제까지 다뤄야 할 수 있습니다.

**2. 생성형 비전 모델 : "만들어내는 AI"**

텍스트나 이미지를 입력받아 새로운 이미지를 만들어내는 모델입니다. Stable Diffusion(Stability AI), GPT Image(OpenAI), Nano Banana / Nano Banana Pro(Google Gemini) 등이 현재 현역으로 쓰이는 대표 모델입니다. 이미지 생성 서비스, 이미지 편집·보정 서비스 등이 여기 속합니다.
LLM 서비스와 비교하면 판별형과는 또 다른 차이가 있습니다.

**모델 서빙 방식** - 디퓨전 모델은 한 번의 요청에 여러 스텝의 반복 추론(denoising step)이 필요해서, LLM의 토큰 단위 스트리밍보다는 "긴 단일 작업(job)을 처리"하는 구조에 가깝고, 요청당 GPU 점유 시간이 훨씬 깁니다.

**데이터 파이프라인** - 실시간 스트리밍보다는 생성 요청을 큐에 쌓고 비동기로 처리한 뒤 결과 이미지를 저장·전달하는 구조(작업 큐 + 오브젝트 스토리지)가 중심이 됩니다.

**지연시간 요구사항** - 실시간 탐지만큼 촉박하지는 않은 대신, "생성 품질과 속도의 트레이드오프"(스텝 수 조절, LCM 같은 경량화 기법)가 핵심 이슈가 됩니다.

**파인튜닝(Fine-tuning) 방식** - 이미지 생성 모델은 LoRA(Low-Rank Adaptation) 여러 개를 동시에 병렬로 붙여 쓰는 경우가 흔합니다. 예를 들어 "캐릭터 스타일 LoRA" + "특정 화풍 LoRA" + "포즈 LoRA"를 각각 다른 가중치로 함께 적용해서 원하는 결과를 조합해낼 수 있습니다. 이미지의 스타일·구도·개체 같은 요소들이 비교적 서로 분리되어(disentangle) 있어서, 여러 LoRA를 합성해도 상대적으로 안정적으로 작동하기 때문입니다.
반면 LLM은 보통 하나의 LoRA 어댑터를 하나의 태스크·도메인에 맞춰 학습하고, 서빙 시에도 요청에 따라 어댑터를 교체하는 방식(멀티 LoRA 서빙, 예: S-LoRA)이 일반적입니다. 언어적 의미는 여러 요소가 서로 얽혀(entangle) 있는 경우가 많아, 여러 LoRA를 동시에 합쳐 쓰면 충돌이나 품질 저하가 발생하기 쉽기 때문에 자유롭게 병렬 결합하지 않습니다.

**3. 한 걸음 더 : 물리적 행동까지 이어진다면**

만약 지원하시는 회사가 로봇, 매니퓰레이터, 자율주행, 드론처럼 물리적 장치를 제어하는 제품을 다룬다면, 이야기가 한 층 더 확장됩니다. 이 경우에는 인식이나 생성에서 그치지 않고, 비전 입력과 언어 지시를 함께 받아 실제 물리적 행동(action)을 출력하는 VLA(Vision-Language-Action) 모델까지 다뤄야 할 수 있습니다. 이는 Physical AI(임베디드 지능) 영역으로, 앞서 정리한 두 갈래와는 또 다른 층위의 설계 지식이 필요합니다.
채용 공고나 프로젝트 설명에 다음과 같은 단서가 있는지 확인해보시면 어느 층위를 준비해야 할지 가늠하는 데 도움이 됩니다.
- "detection", "classification", "recognition" → 판별형 비전 모델
- "generation", "diffusion", "text-to-image" → 생성형 비전 모델
- "action", "control", "manipulation", "policy" → VLA / Physical AI


**마무리**
정리하면, 비전 모델은 판별형과 생성형으로 먼저 나눠 이해하시고, 필요하다면 VLA/Physical AI까지 확장해서 준비하시면 됩니다. 이 세 층위를 다 알아두시면 면접 질문의 방향에 따라 유연하게 대응하실 수 있을 것입니다.
